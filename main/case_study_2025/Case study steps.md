# Case study 2025

This document explain how to run the code for the 2025 case study of the MS5 asset performance program.

## Set up environment
The guide covers execution in the terminal using `git bash` for windows or the regular terminal for WSL.

Start by changing the directory to the root of the repository:
```
cd <your path here>/ms5-asset-performance
```

Create and activate a new virtual environment named `.venv` (or whaterver name you like):
```
python -m venv .venv
source .venv/bin/activate
```

Install the necessary requirements:
```
pip install -r requirements.txt
```

## Data preparation

First create the datasets needed for training the surrogate model and for the Monte Carlo Simulation (MCS). The former samples are drawn from a uniform distribution and the latter from a normal one, parameterized by the prameters given in `/main/case_study_2025/data/parameter_distributions.csv`. You can achieve this by running:
```
python -m main.case_study_2025.prepare_data.prepare_samples.generate_samples --n_mc_samples 10000000 --n_srg_samples 10000
```

You can change the number of drawn samples for the MCS and surrogate training by adjusting the respective argument. The samples are automatically stored in `main/case_study_2025/data`.
This script also calculates the D-SheetPiling results for each of the drawn surrogate samples. The results are also stored in the same directory.

The case study works with synthetic data (corrosion measurements and deformations per time step), which is generated by running:
```
python -m main.case_study_2025.prepare_data.prepare_samples.generate_setting --interval 1
```
The argument `interval` controls the year interval between observations.

## Training the surrogate model

The case study trains a Multi-Layer Perceptron (MLP) neural network as a surrogate model. The MLP models the maximum absolute moment developed long the wall. The input of training are the surrogate samples, while the training target is the maximum absolute moment developed per input sample as estimted by D-Sheet{iling.

You can train the surrogate using:
```
pyhton -m main.case_study_2025.train.surrogate.mlp_moments_train --epochs 10_000 --lr 0.0001
```

The results of training (diagnostic figures, data scalers and trained weights) are stored in `main/case_study_2025/results/surrogate/mlp_moment`.

## Evaluating the timeline

++++ ref to EC7 corrosion model

The next step is to assess the reliability of the sheet pile wall along the timeline of the setting of the case study. This includes:
* Pre-training an MCS dataset: the code generates a grid of corrosion ratios and performs an MCS per point of the grid, using the drawn MCS samples and the trained surrogate model. Per value of the corrosion ratio, the stiffness and moment capacity of the sheet pile wall changes. In this way, the code calculates and caches the conditional probability of failure given the value of the corrosion ratio and during the analysis it only needs to calculate the total failure probability as the expectation of the conditional ones. This is controlled by the PDF of the corrosion ratio, which is dependent on time (through the implemented corrosion model) and the information extracted via updating with the available data.
* Updating forecasts based on available data: the code can update the forecasts of the corrosion ratio PDF using the available corrosion data, as well as the moment capacity based on empirical moment measurements. This leads to 4 combinations of the failure probability calculation to be calculated per forecasting timestep based on: prior/posterior corrosion ratio PDF, using the theoretical (starting) or empirical moment capacity. 
* Estimating the failure probability / reliability along the timeline: by updating the corrosion ratio PDF and the moment capacity, the probability of failure is calculated using the pre-calculated MCS results of the previous step, meaning that the MC simulations do not need to be repeated for estimating each timestep.

To run the timeline analysis use:
```
pyhton -m main.case_study_2025.reliability.timeline_analysis
```

## Visualization
The results of the timeline analysis are visualized by running:

